## 定位

场景题考的不是八股背诵，而是三件事：**需求拆解能力**（先问清楚边界，别上来就画架构）、**高并发一致性设计**（不超发、不少发、可幂等）、**取舍意识**（主动说出方案代价与兜底）。

答题顺序固定：需求澄清 → 架构分层 → 核心算法 → 数据模型 → 主流程 → 并发瓶颈 → 兜底对账。

## 通用答题框架（适用于所有场景题）

1. **澄清**：类型 / 规模（峰值 QPS、数据量）/ 一致性要求 / 时效规则
2. **架构**：接入层 → 服务层 → 存储层，标出读写路径与异步链路
3. **核心算法**：给出算法思路与关键代码
4. **数据模型**：表结构 + 索引 + 唯一键（幂等落到这里）
5. **并发**：竞争点在哪、用什么原子操作打散、如何限流削峰
6. **兜底**：失败重试、死信、对账、降级

## 学习建议

1. 场景题没有标准答案，但有**可验证的抓手**：精度、幂等、并发竞争点、失败兜底——答全这四点就能到「良好」
2. 每个场景题都要能往下追两层：为什么这么拆、这么拆在什么情况下会失效
3. 建议每答完一道场景题，回到对应主题目录补齐原理（如红包 → Redis 原子操作 → `../redis/redis-04-single-thread-model.md`）
