## 三、一页背诵精简版（面试前快速过）

### 大模型基础

1. **LLM**：大语言模型，基于 Transformer 注意力机制，具备长文本理解与生成能力
2. **Token**：模型处理文本的最小单位，输入输出都计费；中文比例因分词器而异（粗估 1~2 汉字/token，以目标模型实测为准）
3. **Zero-shot / Few-shot**：不给示例 / 少量示例；**CoT 思维链**：引导模型分步推理
4. **SSE**：服务端推送实现流式打字效果；服务端 `SseEmitter`，客户端 WebClient 异步接收，处理断流重试
5. **公有 API**：接入快、运维轻；**私有化**：数据不出内网、延迟可控，但运维成本高

### RAG（重中之重）

1. 检索增强生成：私有文档向量化检索，相关片段拼入 prompt 交给 LLM，解决知识滞后、私有数据问答、降低幻觉
2. 链路：文档加载 → 清洗 → Chunk 分片 → Embedding → 向量库 → query 向量化 → 相似度召回 → 可选 Rerank → 拼 prompt → LLM 生成
3. Chunk 过大相似度下降、过小语义不完整；overlap 防语义切断
4. 向量库选型：小业务 PgVector（复用 PG）、海量 Milvus、原型 Chroma
5. 幻觉工程解法：prompt 约束、引用原文、检索结果过滤、拒绝回答
6. RAG vs 微调：RAG 适合频繁变更/私有知识，改文档只更新向量库；微调适合固定风格格式，改动要重训，成本高

### Agent 智能体

1. Agent = LLM 大脑 + 工具调用 + 记忆 + 规划
2. Tool 调用：LLM 输出结构化 JSON 指令，Java 后端解析执行，结果回传模型继续推理
3. 上下文：Redis 存对话历史；token 上限做截断、摘要压缩
4. 风险控制：最大迭代次数防无限循环；控制单次工具返回数据量防 token 爆炸

### Java 工程落地（主场）

1. 架构：文档预处理服务 + 向量检索服务 + 对话网关服务 + LLM 客户端组件
2. IO 密集：异步 WebClient；Java 21 虚拟线程
3. 稳定性：Sentinel 熔断降级，重试幂等防重复计费
4. 限流：用户 QPS / 全局 QPS / token 额度多维度
5. 成本：高频缓存、上下文摘要压缩、简单请求换小模型、token 埋点告警
6. 数据同步：文档增删改同步更新向量库，软删除 + 增量更新
7. 监控：QPS、首 token 耗时、总耗时、输入输出 token、错误码、向量检索耗时、召回率

### 安全与风险

1. Prompt 注入防护：结构化模板、系统指令与用户输入分隔标记、禁裸拼字符串
2. 数据隐私：敏感业务选私有化部署
3. 内容风控：模型输出接内容安全审核接口

## 追问链 · 参考答案

| 层级 | 问题 | 参考答案要点 |
| --- | --- | --- |
| L1 | RAG 的完整链路是什么？Agent 的四要素是哪四个？ | RAG 链路：文档加载 → 清洗 → Chunk 分片 → Embedding → 入向量库；在线侧 query 向量化 → 相似度召回 TopN → 可选 Rerank → 拼 prompt → LLM 生成。Agent 四要素：LLM 大脑 + 工具调用 + 记忆 + 规划。工程上注意：Chunk 分片要带 overlap，记忆层用 Redis 存历史并做摘要压缩。 |
| L2 | Chunk 为什么定在 500+100？PgVector 为什么就够用？ | Chunk 太大向量被多主题「平均」导致相似度下降，太小语义不完整，通用文档取 500 字符 + 100 overlap 起步，overlap 防止一句话被切断在边界；结构化文档优先按标题切。PgVector 够用是因为数据量百万级以内且复用现有 PG，零新增中间件运维，失败面最小；量上亿再换 Milvus。 |
| L3 | SSE 断连怎么重试？重试怎么防止重复计费？ | SSE 断连：客户端带最后事件 ID 重连，服务端感知断连后协作式取消下游 LLM 请求，避免白烧 token；长连接要发心跳防 Nginx 掐空闲连接。计费幂等：LLM 按次计费，重试带请求唯一 ID 做幂等键，只对连接拒绝、5xx 这类明确失败重试，流式已吐一半的不重试。 |
| L4 | 项目里 ReAct 和自由循环怎么取舍的？注入规则为什么前置？ | 步骤可枚举的任务用有界 function-call 循环（如搜车分支 ≤3~5 轮，到轮强制汇总），步骤不可枚举的才用 ReAct 自由循环（金融分支 ≤50 轮看门狗）——本质是确定性用 Workflow 兜住、不确定性圈定范围。注入规则前置用正则快筛，在进 LLM 之前拦截，零 token 成本。 |
| L5 | 流量放大 10 倍，架构哪一层先崩？怎么改？ | 最先崩的是 LLM 供应商配额和线程池，不是自己的服务——LLM 调用是 IO 密集，几秒到几十秒一个。改法：全局限流前置保护配额、队列削峰、高频 query 语义缓存提升命中率、线程池隔离 LLM/检索/解析三路、场景分级换小模型；配套 token 埋点告警盯住成本曲线。 |
